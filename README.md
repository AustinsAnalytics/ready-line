# Ready Line

**Can a better model buy readiness?** An end-to-end sustainment analytics study on public data. It predicts when jet engines need to come off the wing, simulates what that does to a fighter squadron's mission-capable rate, and optimizes the spares and depot plan that hits the target.

By **Austin Gentile** · B.S. Mathematics & Data Science, Centre College (May 2027)

The deliverable is a static website (`site/`) that tells the story with interactive charts, a day-by-day squadron status board, and an in-browser version of the fleet simulator. Every number on the page is generated by the pipeline in `pipeline/`. The page text is a template filled from the pipeline's JSON outputs.

## Headline results

| Question | Method | Result |
|---|---|---|
| Do engines wear out? | Weibull MLE, likelihood-ratio test vs. exponential (709 engines) | β = 3.36 [3.19, 3.53], p < 10⁻²⁴⁰: strong wear-out |
| Is there a hidden fault mode? | PCA + Gaussian mixtures (BIC) + Hartigan dip test | Recovered the documented 1 vs. 2 fault modes without labels; the second mode lives ~87 cycles longer |
| How well can we predict remaining life? | LightGBM + 1D-CNN (PyTorch, Apple GPU), engine-grouped CV, conformal intervals | RMSE 11.1 (FD001), 4.7 cycles where true RUL ≤ 60, on NASA's withheld test engines |
| Which failures interrupt flights? | Logistic regression on 68,264 in-flight FAA reports | Engine problems: adjusted odds ratio 2.36 [2.24, 2.49] |
| Can write-ups be auto-coded? | TF-IDF + linear model, temporal holdout (2024–25) | 89.9% accuracy across 39 aircraft systems |
| What does prediction buy? | GPU-vectorized Monte Carlo of a 24-jet squadron replaying the model's real predictions | MC rate 59.9% → 63.8%; unscheduled engine removals −98% |
| How should spares change? | METRIC-style availability model, Pyomo + HiGHS MILP frontier | Same availability as a rule-of-thumb stocking plan for 35% less |
| Which engines go to the depot when? | Induction-scheduling MILP, scored against withheld truth | 33 in-service failures vs. 51 for a threshold rule, same number of inductions |

The non-obvious finding: **a model buys readiness, a better model mostly buys money.** Once there is any reasonable warning, spares and depot turnaround become the binding constraint, and extra accuracy shows up as fewer wasted engine cycles rather than more sorties.

## Pipeline

| Stage | File | What it does |
|---|---|---|
| 0 | `00_download.py` | Downloads NASA C-MAPSS and FAA SDR CSVs (2016–2025) |
| 1 | `01_spark_etl.py` | PySpark: parse, clean, decode and partition 624k SDRs; unify C-MAPSS, cluster operating regimes (Spark ML), regime-normalize, rolling-window features |
| 2 | `02_warehouse.py` | DuckDB star schema and descriptive SQL |
| 3 | `03_explore.py` | Regimes, sensor ranking, health index, unsupervised fault-mode discovery |
| 4 | `04_hypotheses.py` | Five hypothesis tests, Weibull reliability, age-replacement optimization |
| 5–7 | `05_rul_gbm.py`, `06_rul_cnn.py`, `07_evaluate.py` | RUL models, GPU CNN, ensemble, conformal intervals, SHAP, simulator profiles |
| 8 | `08_nlp_sdr.py` | Write-up classifier, miscode detection, NMF failure-mode topics |
| 9 | `09_forecast.py` | Fleet demand (ETS, SARIMAX) and intermittent part demand (Croston, SBA, TSB) |
| 10 | `sim_engine.py`, `10_simulate.py`, `10b_board.py` | Fleet readiness simulator, policy comparison, value of prognostics, surfaces, analysis of alternatives, sensitivity |
| 11 | `11_optimize.py` | Spares MILP frontier, depot induction scheduling |
| 12 | `validate_js_sim.js`, `12_build_site.py` | Check the browser simulator against Python; render the site |

## Reproduce

Requirements: Python 3.12, Java 8/11/17 (for PySpark), Node 18+ (for the simulator check). About 1 GB of disk for data.

```bash
python3.12 -m venv .venv
```

```bash
source .venv/bin/activate && pip install -r requirements.txt
```

```bash
make all
```

```bash
make serve
```

`make all` takes about 45 minutes on an Apple M2 laptop; most of that is stage 10 (several hundred thousand simulated squadron-years). The deep-learning stage uses an Apple GPU (MPS) or CUDA when available and falls back to CPU. `make site` rebuilds only the web page from existing results.

## Deploy the website

`site/` is fully static and needs no build step on the host. It also works opened straight from disk, because all data ships in `site/data/bundle.js`.

1. Put your repository link in `site_config.json` (for example `{"repo_url": "https://github.com/<you>/ready-line"}`), then run `make site`.
2. Pick one host:
   - **GitHub Pages:** push this repo to GitHub, then go to Settings → Pages → Source: *GitHub Actions*. The included workflow (`.github/workflows/pages.yml`) publishes `site/` on every push to `main`.
   - **Netlify:** drag the `site/` folder onto app.netlify.com/drop.
   - **Vercel:** `vercel deploy site --prod`.
